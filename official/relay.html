Server Monitor

Run your own relay

You need a relay only if other people should watch your servers. It runs on a machine you choose, so team traffic never passes through appinsource. A setup assistant installs it in a few minutes.

What the relay does

Think of it as a mailbox. A team member's phone leaves a request in the mailbox. Each server checks the mailbox by itself, picks up the request, and leaves the answer there. Because the servers connect out, none of them opens a port.

You do not need a relay for yourself. Your own iPhone reaches your servers directly over SSH.

What you need

  • One Linux machine with systemd that the internet can reach on ports 80 and 443. It can be one of your servers.
  • A domain name with an A record that points to that machine, for example relay.example.com.
  • Root access on that machine, once.

Install it

  1. Download the relay for your machine on that machine: 
    curl -fsSLO https://monitor.appinsource.eu/downloads/srvmon-relay-linux-amd64.tar.gz
curl -fsSLO https://monitor.appinsource.eu/downloads/SHA256SUMS
sha256sum -c SHA256SUMS --ignore-missing
tar -xzf srvmon-relay-linux-amd64.tar.gz
    On an ARM machine, use arm64 instead of amd64.
  2. Start the assistant: 
    cd srvmon-relay
sudo ./setup.sh
  3. Answer its questions. It asks for the domain, checks DNS, picks a free local port, and finds your web proxy. Caddy and Nginx are set up for you. With no proxy it offers to install Caddy. It shows what it will change and asks before it changes anything.
  4. At the end it prints the relay address and the admin token. Keep the token private.

Connect the app

  1. In the app, open Team and tap Set up relay.
  2. Enter the relay address and the admin token.
  3. Choose the servers to connect. The app tells each server's agent where the relay is, over your SSH login.
  4. Invite people. Each one joins with a QR code and sees only what you allow.

Security

  • The relay runs as its own system user, without root, and listens only on the machine itself. The web proxy handles HTTPS.
  • Each member's phone signs every request. The agent checks the signature and the member's role itself, so the relay cannot give orders to your servers.
  • Members get no SSH and no terminal. File requests are refused.
  • The relay can read the team traffic that passes through it. That is why it should run on a machine you trust.

Move it later

The relay keeps everything in one data folder and one token. Copy both to the new machine and point the domain there. With the same domain, servers and phones reconnect by themselves. With a new domain, connect the servers again and send new invites.

If something goes wrong

What you seeWhyWhat to do
https://… does not answerDNS does not point here yet, or ports 80 and 443 are closedCheck the A record and the firewall, then run sudo ./setup.sh again. It keeps your token and data.
The relay does not answer on the machineThe service did not startjournalctl -u srvmon-relay -n 30
Servers keep going offlineThe proxy cuts waiting requestsSet the proxy's read timeout to 60 seconds or more and turn response buffering off.
